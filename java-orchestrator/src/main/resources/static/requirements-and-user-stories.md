# Project Requirements & User Stories: Local RAG Chatbot

## Project Overview
I am building a fully localized Retrieval-Augmented Generation (RAG) chatbot to process internal Standard Operating Procedures (SOPs). The primary driver for this project is security: I need a system that can answer operational questions accurately without sending sensitive company data to external cloud APIs like OpenAI. Following a recent review session with our Senior Analyst and the team's Operational Lead, I have mapped out the core requirements and prioritized them to ensure we deliver a secure, air-gapped solution that still feels modern and responsive.

## MoSCoW Prioritization

### Must Have (Critical for MVP)
- 100% local execution for all data processing and LLM inference.
- Automated ingestion of PDF documents from a designated local folder.
- Semantic search capabilities that retrieve relevant text chunks.
- Explicit citations in the chatbot's answers, including the exact document name and section header.
- A secure local login mechanism to restrict access.

### Should Have (Important but not critical for initial launch)
- A conversational web interface that feels familiar (similar to ChatGPT).
- A polyglot architecture separating the heavy AI workloads from the file orchestration.

### Could Have (Nice to have if time permits)
- An automated cron job or scheduler that detects new PDFs the moment they are dropped into the folder.

### Won't Have (Out of scope for now)
- Cloud deployment or third-party API integrations.
- Multi-user concurrent session handling with distinct role-based permissions.

## User Stories

**US-01: Secure Access**
- **As a** system user,
- **I want** to authenticate using local credentials,
- **So that** unauthorized users cannot access or query our confidential SOP data.
- **Acceptance Criteria:** The application must present a login screen on launch. Only valid local credentials will grant access to the chat interface.

**US-02: Automated Document Ingestion**
- **As an** administrator,
- **I want** the system to automatically scan my designated local directory and chunk any PDF documents it finds,
- **So that** our knowledge base stays up to date without manual data entry.
- **Acceptance Criteria:** The Java orchestrator successfully detects `.pdf` files and passes them to the Python engine, which splits the text into chunks of 1000 characters with a 200-character overlap.

**US-03: Accurate Retrieval & Citations**
- **As a** staff member querying the system,
- **I want** the chatbot to answer my questions while explicitly citing its sources,
- **So that** I can trust the information and easily verify it against the original document.
- **Acceptance Criteria:** Every response generated by the LLM must include the source document title and the relevant section header. If the answer is not in the text, the AI must explicitly state "I don't know."

**US-04: Polyglot System Architecture**
- **As a** developer,
- **I want** to separate my file management logic from my AI processing,
- **So that** the system is scalable, modular, and easier to maintain.
- **Acceptance Criteria:** A Java Spring Boot backend will handle file system events and API routing, passing the data securely to a Python FastAPI microservice that handles the LangChain and ChromaDB workloads.
